DO-178C documents

The document library, how sections are authored from the workspace and by agents, how engineering decisions are reviewed, and how documents are issued, baselined and exported to Word.

The document library#

Open DO-178C Documents from its tile or Noyce Compliance: Open DO-178C Documents.

The library holds the 17 DO-178C life-cycle documents:

Group Documents
Plans PSAC, SDP, SVP, SCMP, SQAP
Standards SRSTD, SDSTD, SCSTD
Core SRS, SDD, ICD, TRACE
Verification SVCP, SVR
Summary SECI, SCI, SAS

Filter by group, search, sort by kind, and switch between Grid and List. Export all writes every document to Word; Regenerate stale re-authors documents whose workspace inputs have changed. Each card shows the document's revision, date and baseline state.

Documents are stored as StrictDoc .sdoc files in .noyce/documents/, so they are plain text you can diff.

Author a document#

The split matters for review. Facts from the workspace are checkable against the project. Engineering judgment, such as why a tool needs no qualification or how independence is achieved, is the part an auditor will question, so it is always drafted as a proposal and decided by a person. Prose fills in the rest.

Open a document from the library, or create one with Create from template.

  1. From the workspace, no model. Sections whose content is a fact about the project, such as the toolchain, the source files, the target and the tools in use, are filled from the workspace when the document is created.
  2. Decisions, drafted by an agent. Select Propose decisions and an agent drafts each section that needs engineering judgment. Each draft is marked PROPOSED, awaiting engineer review and counts for nothing until a person accepts it.
  3. Prose, by the docs swarm. Write an instruction and select Run docs swarm, or use Author set… to author several documents in one go. Each section is saved as soon as it is written, so stopping and restarting picks up where it left off. Improve with model also revises the template prose.

Review decisions#

When drafts are waiting, the document shows how many decisions await your review. Select Review decisions, pick yourself as the reviewer, and for each draft:

  • Accept it as written,
  • Edit and accept it with your changes, or
  • Reject it with a comment that the next draft has to answer.

If the fact check flags a draft, accepting it needs Accept over fact check…, so the override is on record. Every accepted decision is stored as a review and in the audit trail.

Complete and issue#

The Completion tab lists what stands between the document and issue: proposals to review, engineering decisions to answer, evidence the workspace has not produced yet (Refresh from workspace checks again), and contradictions with other documents (Re-check, or waive with a reason).

When it is clear, choose the signatories from the roster and select Sign and issue (baseline). The issued revision is frozen with a SHA-256 hash of its content. Later edits become a new revision: Record revision asks what changed.

SVR and SAS cannot be issued until the latest compliance run shows that verification was executed. When the set is ready, Declare set baseline records the whole set against the current git commit.

Export to Word#

Select Export .docx on a document, or Export all in the library. The export is a formal document with a cover page, contents, numbered headings, tables, and Mermaid and Archify figures rendered as images.

To match your company's format, open Document template… and select Import from .docx… with one of your Word documents. Noyce IDE takes its styles, header and footer, page setup and logo, and suggests a cover. Save template applies it to every export; Reset to built-in goes back.

Document Reader#

Read and edit the issued Word documents and certification packages in place. Open it with Noyce: Document Reader.

Markdown and PDF#

.md files open in a WYSIWYG Markdown editor that saves to the file as you type, with normal undo. PDFs open in the built-in PDF viewer.
