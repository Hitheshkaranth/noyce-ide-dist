DO-178C documents

The document library, how sections are authored from the workspace and by agents, how engineering decisions are reviewed, and how documents are issued, baselined and exported to Word.

The document library#

Open DO-178C Documents from its tile or Noyce Compliance: Open DO-178C Documents.

The library holds the 17 DO-178C life-cycle documents:

Group Documents
Plans PSAC, SDP, SVP, SCMP, SQAP
Standards SRSTD, SDSTD, SCSTD
Core SRS, SDD, ICD, TRACE
Verification SVCP, SVR
Summary SECI, SCI, SAS

Filter by group, search, sort by kind, and switch between Grid and List. Export all writes every document to Word; Regenerate stale re-authors documents whose workspace inputs have changed. Each card shows the document's revision, date and baseline state.

Documents are stored as StrictDoc .sdoc files in .noyce/documents/, so they are plain text you can diff.

Author a document#

The split matters for review. Facts from the workspace are checkable against the project. Engineering judgment, such as why a tool needs no qualification or how independence is achieved, is the part an auditor will question, so it is always drafted as a proposal and decided by a person. Prose fills in the rest.

Open a document from the library, or create one with Create from template.

The document editor#

An open document has three tabs:

  • Nodes shows the document's sections in order, read-only, with each section's UID. Text renders as Markdown, and Mermaid and Archify diagram blocks render as figures. Sections an agent drafted carry Proposed — awaiting review; accepted ones carry Decided. The document control page with its revision history sits at the top.
  • Decisions · N is the queue of agent-drafted sections waiting for your review.
  • Completion lists what stands between the document and its issue, and holds the Sign and issue button.

Sections are not typed into directly. Text comes from the workspace, from the docs swarm, from accepted decisions, and from the answers you give in the Completion tab, so every sentence has a recorded source.

  1. From the workspace, no model. Sections whose content is a fact about the project, such as the toolchain, the source files, the target and the tools in use, are filled from the workspace when the document is created.
  2. Decisions, drafted by an agent. Select Propose decisions and an agent drafts each section that needs engineering judgment. Each draft is marked PROPOSED, awaiting engineer review and counts for nothing until a person accepts it.
  3. Prose, by the docs swarm. Write an instruction and select Run docs swarm, or use Author set… to author several documents in one go. Each section is saved as soon as it is written, so stopping and restarting picks up where it left off. Improve with model also revises the template prose.

Review decisions#

When drafts are waiting, the document shows how many decisions await your review. Select Review decisions, pick yourself as the reviewer, and for each draft:

  • Accept it as written,
  • Edit and accept it with your changes, or
  • Reject it with a comment that the next draft has to answer.

If the fact check flags a draft, accepting it needs Accept over fact check…, so the override is on record. Every accepted decision is stored as a review and in the audit trail.

Accept N routine accepts the routine drafts in one step. It never includes a draft marked safety-critical or one that contradicts another document; those are always decided one at a time.

Regenerate a document#

When the project changes, a document's workspace facts go stale. The library marks it, and Regenerate stale (N) or a document's own regenerate icon builds a new version and shows it before anything is saved:

  • every section is labelled Updated, Reset for re-authoring, Kept or Unchanged, with Show diff for a line-by-line comparison;
  • an issued document is flagged because saving returns it to draft;
  • Save as new revision archives the current revision first and saves the new one; Cancel changes nothing.

Sections reset for re-authoring are written again by the docs swarm.

Complete and issue#

The Completion tab shows the document's state (Awaiting review, Open items remain, Ready to issue, Issued or Changed since issue), a progress bar, and four numbered lists:

  1. Agent proposals awaiting review, with a shortcut to the Decisions tab.
  2. Engineering decisions, answered by the Responsible engineer you name.
  3. Waiting for workspace evidence: facts the project has not produced yet. Refresh from workspace checks again; the engineer can also record them directly.
  4. Cross-document consistency: contradictions with other documents, each marked Blocks issue or Warning, which you fix or waive with a reason.

When it is clear, choose a person from the roster for each approval role and select Sign and issue (baseline). The issued revision is frozen with a SHA-256 hash of its content, and the audit trail gets one entry for the baseline and one per signature. Later edits become a new revision: Record revision (enabled once the saved content differs from the last recorded version) asks "What changed since vx?" and records it.

SVR and SAS cannot be issued until the latest compliance run shows that verification was executed. When the set is ready, Declare set baseline records the whole set against the current git commit.

Export to Word#

Select Export .docx on a document, or Export all in the library. The export is a formal document with a cover page, contents, numbered headings, tables, and Mermaid and Archify figures rendered as images.

To match your company's format, open Document template… and select Import from .docx… with one of your Word documents. Noyce IDE takes its styles, header and footer, page setup and logo, and suggests a cover. Save template applies it to every export; Reset to built-in goes back.

Document Reader#

Read and edit the issued Word documents and certification packages in place. Open it with Noyce: Document Reader.

Select a document to read it as the formal Word document it exports to: cover page, document control, numbered headings, tables and figures, with your template applied.

The library lists the DO-178C documents, Markdown and Word files the agents wrote under .noyce/, and certification packages. Read shows the page; Reload reads it from disk again. Edit opens the Word file in an in-place editor with Save and Cancel. While the docs swarm is writing the open document, the page refreshes about every 12 seconds.

Warning

Edit changes only the .docx file. For a DO-178C document or a Markdown-based document, the next open or Reload rebuilds the .docx from its source and discards those edits. Make lasting changes through the document editor instead.

Markdown and PDF#

Markdown files (.md, .markdown) open in a WYSIWYG editor by default. Your edits go back into the file about a quarter of a second after you stop typing, so saving, the unsaved-changes dot and undo all work as usual, and changes made to the file elsewhere (for example a git checkout) appear in the editor. MISRA squiggles are not shown in this editor.

PDF files open in the built-in viewer, which works offline: thumbnails, page navigation, zoom (⌘+ and ⌘−), rotate, find (⌘F, then Enter and ⇧Enter between matches), copy the file path, and open in your system viewer.
