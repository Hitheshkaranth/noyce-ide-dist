Annex A objective tables

Which DO-178C Annex A applicability and independence table a project grades against - the built-in table, two-person verification and overrides, or an imported licensed table - and what each means for your plans.

Every objective in DO-178C Annex A applies, applies with independence, or does not apply, depending on the software level. Grading, the Compliance Run and the PSAC, SVP, SCMP, SQAP and SAS all read that table. Noyce IDE can take it from three places, in this order of precedence:

Source Badge What it carries Plans
A licensed table you imported Imported Applicability, independence, control category, section references and outputs, entered from your licensed copy. Can be issued.
The built-in table, verified Built-in, verified Applicability and independence only. Can be issued; control categories read "Not entered".
The built-in table, not verified Built-in, unverified Applicability and independence only. Stay draft.

You see the source on the Compliance Dashboard header line Annex A table, with Verify… and Import licensed table… beside it, and in Evidence Records → Annex A table.

The built-in table#

Noyce IDE ships a matrix of the 71 objective ids against levels A to E: applies with independence, applies, or not applicable. It contains no objective wording, outputs, control categories or section references; those are RTCA's licensed text and come only from an imported table.

The matrix is the product author's transcription. Its totals match the widely cited DO-178C totals (applicable A 71, B 69, C 62, D 26, E 0; with independence A 30, B 18, C 5, D 2), but a matching total does not prove every cell. That is why it counts for your project only after two people have checked it against a licensed copy. Every built-in cell carries the provenance declared, producer noyce.builtin-annex-a.

While the table is unverified, the Compliance Dashboard shows the notice Annex A from built-in table, not verified: "PSAC, SVP, SCMP, SQAP and SAS stay draft until two rostered people verify it, or a licensed table is imported." Those documents carry the note "Applicability from built-in table — not yet verified against a licensed copy", and an issued one says it is not for submission.

Verify the built-in table#

Two different people on the roster each confirm every cell against their own licensed copy. Add both to the roster first; with fewer than two people the panel says "The roster needs two people".

  1. Select Verify… on the Compliance Dashboard, or open Evidence Records → Annex A table.
  2. Choose yourself under Verifier and name your copy under Licensed copy (for example the RTCA document and licence number).
  3. Pick a table (A-1 to A-10). For each objective and level, the cell shows Built-in: and its value. Set what your copy says: Agree — … or Disagree — … with the value your copy gives. Cells marked check first are the ones the author is least sure of.
  4. Agree with the rest of A-n marks every cell you have not touched in that table as agreeing. Use it only after reading the table.
  5. When all 355 cells (71 objectives × 5 levels) are marked, select Sign verification.

The table becomes Built-in, verified when:

  • two distinct people on the roster have each signed a verification (an AI identity never counts),
  • every value each of them stated equals the effective value of every cell, and
  • neither record is stale. Each record carries the SHA-256 of the matrix it checked; if a product update or an override changes any cell, the record stops counting ("matrix changed since verification; verify again").

A person who verifies again replaces their own earlier record. Records are stored one file per record under .noyce/process/annex-a-verification/.

Resolve a disagreement with an override#

A disagreement does not change the table by itself. Under Disagreements to resolve, each cell where a verifier's copy differs is listed as "name reads value; matrix has value".

  1. Choose who records the override under Override recorded by (a person on the roster).
  2. Under Reason, say what the licensed copy states and where.
  3. Select Override to value.

The override is itself a signed record and changes the effective cell for this project. Because the matrix changed, any verifier who agreed with the old value has to verify again.

Import a licensed table#

If your organisation holds the licensed DO-178C text, import the full table instead. Run Noyce Compliance: Import Licensed Annex A Table (applicability, independence), or select Import licensed table… on the Compliance Dashboard.

  1. Open blank template writes a template with the 71 objective ids and opens it. Fill every empty value from your licensed copy and save.
  2. Load filled template reads it into the form, or paste the table JSON. The form lists what is still missing: objectives, applicability or independence per level, section references, outputs or control categories.
  3. Enter Your name (a person, not an agent) and the Licensed copy, then select Import and sign.

The table is stored in .noyce/compliance/annex-a-licensed.json with its content hash, and takes precedence over the built-in table. Verifying the built-in table changes nothing while an imported table stands.

Limitations#

  • The built-in table carries no control categories, section references or outputs; those read "Not entered — control categories come only from an imported licensed table" until a licensed table is imported.
  • The built-in table has not been verified by Noyce against a licensed copy. Your project's two verifications are what make it usable.
  • ISO 26262 and IEC 61508 have their own built-in method tables with the same verification rules; see ISO 26262 and IEC 61508. IEC 62304 has none.
