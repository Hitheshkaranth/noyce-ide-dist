Architecture & search

Understand an unfamiliar firmware project fast with the Project Graph, a C4 architecture model, Archify diagrams and semantic search over the code.

Project Graph#

Every function, file and macro in the project and how they connect, on one canvas. Open it from the Project Graph activity bar icon, its tile, or Noyce Project Graph: Open Project Graph.

Read it like this

  • Entry flow starts at main and follows the call edges, so you see how the firmware boots and what its loop calls.
  • Code ownership separates your project code from vendor code (TivaWare or STM32 HAL) and generated or boot code.
  • Select a node to see its callers, callees and the macros it uses. Focus Entry recentres on the entry flow; Reset View fits everything.

Cluster by groups the graph to answer different questions:

Cluster by Answers
Directory How is the code laid out on disk?
Layer What is application, middleware, vendor SDK?
Language Where are the C, assembly and headers?
Ownership, Library What is ours and what is the vendor's?
Community Which functions form tightly connected groups (Louvain)?
Blast radius What is affected if the selected function changes?

System Architecture#

A C4 architecture model built from the code. Open it from the Architecture activity bar icon, its tile, or ⌘⌥N then Y.

  1. Choose the analysis mode. Static builds the model from the code graph alone, with no model. AI and Hybrid also ask your model to name and group the subsystems; if the model is unavailable, the static result is shown and labelled as such.
  2. Select Analyze.
  3. Move between levels with the tabs: Context, Containers, Components, Code, Dependencies, Data Flow and Embedded. Select a node for its details.
  4. Export the model as Structurizr DSL, Mermaid, Markdown, Draw.io, JSON, SVG, PNG or PDF, or Save to .noyce to keep it with the project for the SDD.

High-Level Design#

High-Level Design draws a Mermaid architecture diagram of the project with a local model. It sends up to 60 source files in one request of about 14,000 characters, shared between them: small files go in whole and larger ones contribute their opening lines (includes, types and declarations), so one large file cannot crowd out the rest. It draws the diagram, and saves it to .noyce/diagrams/hld.json; the next time you open it with unchanged source, the saved diagram is shown without asking the model again. Scroll to zoom and drag to pan. Regenerate draws it again, Export .md saves it as a Markdown file with the Mermaid block, and Open in Architecture Analyzer returns to the C4 model.

If a line the model wrote is not valid Mermaid, that line is left out, the rest of the diagram is drawn, and a notice above it shows the line. Regenerate asks the model again.

Note

High-Level Design works with any local model (LM Studio, vLLM through the LM Studio provider, Ollama or Open WebUI), and its badge names the model used. The C4 model and Archify work with any model.

Archify Diagrams#

An architecture diagram of the open project, drawn by your model and checked before it is shown. Open it with Noyce: Archify Diagrams or the Archify button in System Architecture.

The model writes the diagram in Archify's structured format, Noyce IDE validates it, and only a valid diagram is rendered. Pick the diagram type and select Regenerate to draw it again. Diagrams are saved to .noyce/diagrams/ and can be placed in DO-178C documents and their Word exports.

Semantic Search#

Ask a question in plain language and get the most relevant code and documentation. Open it from the tile or Noyce: Semantic Search.

  1. Set an embedding server in AI Models → Embeddings and select Save & test. See Connect a model.
  2. Select Build / Rebuild index. The index is stored in .noyce/rag/index.json.
  3. Type a question, for example "where is the RS485 packet checksum verified", and press Enter.

The same index grounds the agents: relevant code is added to their prompts, so their answers cite your project.

Important

Both building the index and every query need the embedding model. If your model server only serves a chat model, queries fail as shown above. Point Embeddings at a server that serves an embedding model, and rebuild the index if you change models.
