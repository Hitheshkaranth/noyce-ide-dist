The .noyce folder

Where Noyce IDE keeps everything it generates for a project, what each file is, and how it stays out of version control.

Noyce IDE never writes generated files into your source tree. Everything it produces for a project (analysis results, documents, evidence, the audit trail, agent state) goes into a .noyce/ folder at the project root.

It stays out of git#

Two things keep the folder out of version control, without changing any file you track:

  • .noyce/.gitignore contains *, so git ignores everything inside.
  • If the project is a git repository, .noyce/ and .codegraph/ are added to .git/info/exclude, which is local to your clone and is never committed.

Important

Because .noyce/ is never committed, your requirements register, review records, issued documents and audit ledger are not in your repository. Back the folder up, or archive it with each release, if those records must be kept. A compliance run records the git commit it measured, so the evidence still points at the exact source.

Layout#

This is the folder from the Canister Main Controller copy used for these docs, plus the locations each surface writes to once it has been used. Folders appear only when the feature that owns them has run.

text
.noyce/

├── audit-ledger.json             hash-chained audit trail
├── orchestrator-tasks.json       the Orchestrator board for this project
├── architecture/                 System Architecture model cache and exports
├── diagrams/                     Archify diagrams, High-Level Design
├── compliance/
│   ├── article-do-178c.json      framework, assurance level and objective article
│   ├── evidence-snapshot.json    the latest dashboard scan
│   ├── static-analysis.json      stored analysis findings
│   ├── annex-a-licensed.json     your licensed Annex A table, once imported
│   └── evidence/                 generated evidence write-ups
├── annex-a/                      objective map and objective text
├── compliance-runs/              one folder per compliance run, plus index.json
├── certification/                certification packages (.md, .html, .json)
├── documents/
│   ├── index.json                the document register
│   ├── PSAC-001.sdoc  …          each life-cycle document, and its .docx export
│   ├── proposals/                agent-drafted decisions awaiting review
│   ├── history/                  frozen revisions with their content hash
│   └── set-baseline.json         the declared document-set baseline
├── templates/                    your corporate .docx template settings
├── requirements/                 imported system requirements, low-level requirements
├── process/                      roster, reviews, problem reports, CCB, MISRA deviations
├── change-sets/                  staged code changes awaiting approval
├── verification/                 test cases, results, CBMC runs, target test runs
├── coverage/                     measured MC/DC per driver
├── manuals/                      the downloaded reference manual (PDF)
├── knowledge/                    the indexed register knowledge base
├── rag/                          the Semantic Search index
└── rules/  notepads/  memories.md   context you give the agents

Safe to delete?#

Delete What happens
rag/, architecture/, knowledge/ Rebuilt the next time you use the view. Re-indexing a manual or the workspace takes a few minutes.
compliance/evidence-snapshot.json Rebuilt by the next dashboard scan.
documents/, process/, audit-ledger.json, compliance-runs/ Lost for good. These are your records: issued documents, human reviews and the audit trail.

Deleting the whole folder returns the project to a fresh state. Your source files are unaffected.
