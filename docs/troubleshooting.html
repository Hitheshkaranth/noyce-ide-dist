Troubleshooting

Fixes for the problems people hit most often, from a Mac that refuses to open the app to a view that says a tool is missing.

Installing and launching#

macOS says the app is damaged or from an unidentified developer#

The disk-image build is not notarized. Clear the quarantine flag, then open the app again:

Terminal
xattr -dr com.apple.quarantine "/Applications/Noyce IDE.app"

Homebrew and the one-line installer do this for you.

Windows shows "Windows protected your PC"#

The beta installer is not code-signed yet. Select More info, then Run anyway.

The window is blank or a view stops responding#

Run Developer: Reload Window from the Command Palette. Your open project and its .noyce/ data are kept.

Models and AI#

A panel says to configure a model first#

The DO-178C Documents panel and the agents need a model before they can draft anything. Open Noyce AI: Open AI Models, select a model and confirm its server URL. See Connect a model.

Semantic Search says "Embedding request failed with status 404"#

The full message looks like this:

text
Search failed
Embedding request failed with status 404: model 'text-embedding-nomic-embed-text-v1.5'
is not being served right now; available: ['ornith-1.5-35b-a3b']

The embedding server does not serve the embedding model, usually because it is the chat server and serves only a chat model. The available list shows what it does serve. In AI Models → Embeddings, point the embedding server at one that serves an embedding model, select Save & test (it reports the vector size it received), then Build / Rebuild index. A vLLM server started for one generative model has no embeddings endpoint at all.

A local model returns empty or cut-off answers#

The server is probably running with a smaller context window than the model supports, or does not report it. Set Context window (tokens) for that model in AI Models to what the server actually runs. With LM Studio, also check the context length you loaded the model with.

Cannot reach a vLLM server on another machine#

Use the LM Studio provider and enter the server's address, for example http://<host>:8000. If the server was started with --api-key, enter the key in API key (only if the server requires one).

Analysis tools#

MISRA findings are labelled "not evidence"#

They come from the built-in heuristic scan, which runs when no analyzer is installed. Install cppcheck (brew install cppcheck on macOS) and select Scan again.

MC/DC says "MC/DC unavailable"#

MC/DC needs LLVM/Clang 18 or newer (clang, llvm-profdata, llvm-cov). gcov cannot measure MC/DC. Install LLVM with brew install llvm on macOS or the LLVM installer on Windows, then run the measurement again.

Formal Verification or Code Scanning says no run yet#

CBMC and CodeQL are not bundled. Select Install CBMC or Install CodeQL in the view, or install them yourself and make sure they are on your PATH. See Optional tools.

Firmware Memory says there is no link map#

Firmware Memory reads GNU and TI Arm linker .map files from a build. For a GNU build, create a map file (-Wl,-Map=<name>.map) and add -fstack-usage for worst-case stack depth. For a TI Arm build, build the project in CCS or Build Pipeline so the .map exists.

Register Knowledge is empty#

The reference manual is downloaded when you import a project with the Import Project wizard, which needs a network connection. Import the project again with the wizard while online, or select Choose PDF… in Register Knowledge to index a manual you already have.

Data and records#

My reviews and documents are not in git#

That is by design: .noyce/ is kept out of version control. See The .noyce folder for how to keep those records.

A change set says it is stale#

A file it changes was edited after the change set was gated. Nothing was written. Propose the fix again on the current code. See Review AI changes.

Still stuck#

Open an issue with your Noyce IDE version (Noyce: About Noyce IDE), your OS, and what you expected to happen.
