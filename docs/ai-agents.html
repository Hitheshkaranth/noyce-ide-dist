AI & agents

The AI Orchestrator and its 15 agents, the agents chat panel, inline edits and next-edit prediction, context and @-mentions, build fixes, commit messages, terminal help and every agent setting.

Every AI feature runs on the model you choose in AI Models. For the screenshots on this page that was Ornith (ornith-1.5-35b-a3b), served by vLLM on a machine on the local network.

AI Orchestrator#

A kanban board where agents work through tasks for this project. Open it with ⌘⌥N then O or Noyce AI: Open AI Orchestrator.

Reading the board

  • The header shows the model in use, its context size, live token rate, and how many calls are running. It is a readout; choose models in Models.
  • The strip shows concurrency, sprint progress, how many cards wait for your review, and the handoff chain of the 15 agents.
  • The columns: To Do (ready for an agent), In Progress (an agent owns it), Handover (the agent is done and you need to review it), Done. Status / By agent switches the grouping.

Adding work

  • Type tasks in Backlog, one per line. Prefix a line with an agent to route it (coder: implement voltage clamp) and add [high] for priority. Then Add to sprint or Add to backlog.
  • Generate via Orchestrator on the Compliance Dashboard adds one card per open objective.
  • Authoring a DO-178C document adds a card for that document.

Running it

  • Run next runs the next card. Run sprint works through the sprint. Run full pipeline runs the multi-agent pipeline on an objective you type in the box next to it.
  • Auto-run keeps the sprint moving as cards finish.
  • Agent output opens one tab per agent with its streamed output, its reasoning, and the actions it took. See Agent Output.

What agents produce. Documents and evidence are written into .noyce/ as drafts for you to review. Code is never written to your files directly: with Auto-apply agent code off you choose Stage all as change set in the agent's output; with it on, the change set is staged for you. Either way it waits in Evidence Records → Change sets for a person to approve.

The board is saved per project in .noyce/orchestrator-tasks.json, so cards from one project never appear in another.

The 15 agents#

Agent Typical work
System Designer Breaks a goal into tasks and design.
Software Engineer Writes code (route with coder:).
Test Engineer Writes tests.
Code Reviewer Reviews changes.
Doc Generator Drafts documents and objective evidence.
Traceability Monitor Checks trace links.
MISRA Code Fixer, CBMC Fixer, CodeQL Fixer Propose fixes for findings, as change sets.
Compliance Author Writes compliance evidence.
Doc Author, Doc Reviewer Author and review DO-178C document sections.
UI/UX Designer, Frontend Developer, API Integrator General roles, not firmware-specific.

Give any agent its own model in AI Models → Agent Role Assignment.

Agents chat#

A chat panel in the secondary sidebar, with a choice of agent persona. Open it with ⌘⇧A or Noyce AI: Open Agents Chat (⌘⌃I).

  • Switch agent with ⌘K ⌘A, attach a file with ⌘⇧O, search the thread with ⌘F, and stop a reply with ⌘..
  • Agent History keeps every thread, with export, delete and re-run.
  • Edits an agent makes from the chat can be undone with Revert Last Agent Edit or Revert All Agent Edits.

In the Code-OSS Chat view, the @noyce participant answers in agent, ask or edit mode and has /fix, /test, /explain and /trace.

In the editor#

These features use the Coder agent and the model assigned to it.

Inline edit#

  1. Select the code to change, or leave the cursor on a line to change only that line.
  2. Press ⌘K ⌘I (Edit Inline…) and describe the change.
  3. The proposal appears in the file: the old lines in red, the new lines in green below them. Enter accepts it, Esc rejects it.

Accepting saves the file, records the edit in the audit trail, and adds a checkpoint, so Revert Last Agent Edit can undo it. Your project rules that match the file are sent with the request. Only one inline edit can be open at a time.

Note

⌘K ⌘I replaces the Code-OSS Show Hover shortcut. Rebind either in Keyboard Shortcuts if you need both.

Completions and next edit#

Both are off by default.

  • Inline completions (noyce.agents.inline.enabled) show ghost text as you type. Tab accepts.
  • Next edit (noyce.agents.inline.nextEdit.enabled, which also needs completions on) predicts the next change you are likely to make elsewhere in the file, after you accept a completion or when you run Predict Next Edit. When a prediction is ready, ⌘⌥] (Jump to Next Edit) moves the cursor there and shows it as ghost text; Tab accepts it and Esc dismisses it. Typing in the file discards the prediction.

noyce.agents.inline.maxLines (12) caps how long a suggestion can be.

Other editor actions#

  • Composer (⌘⌥K) reviews an agent's changes across several files, hunk by hunk. Accepted hunks are staged as a change set.
  • CodeLens actions above functions: Refactor with Coder, Audit MISRA with Reviewer, Generate Tests with Tester.
  • Generate Driver from Datasheet (⌘⌥D) drafts a driver from a datasheet you attach.
  • Fix with Noyce appears as a quick fix on MISRA diagnostics. See Review AI changes.
  • Register hovers: when the workspace has a CMSIS-SVD file, hovering a peripheral register in C or C++ shows its description and fields, and completions are grounded in it. Noyce IDE uses noyce.agents.svd.path or else the first *.svd in the workspace; run Reload SVD File after replacing it.

Context you give the agents#

Kind Command Stored in
Project rules: standing instructions, such as your coding standard Create Project Rule, Show Project Rules NOYCE.md and .noyce/rules/*.md
Notepads: reusable notes you can attach Create Notepad…, Show Notepads… .noyce/notepads/*.md
Memories: facts the agents keep about the project Remember This…, Show Project Memories, Clear Project Memories .noyce/memories.md

Rules and memories are added to every request, up to noyce.agents.rules.maxChars (6,000) and noyce.agents.memories.maxChars (4,000) characters.

In the agents chat, type @ to attach context to one message:

Mention Attaches
@file, @folder A file (up to noyce.agents.context.maxFileBytes, 32 KB) or a folder listing
@symbol A function or type and its neighbours from the code graph
@codebase The most relevant code from the Semantic Search index
@git Your staged changes and the last commit
@requirement A requirement's shall statement, from your requirement documents
@docs Matching passages from the project's docs/ folder
@notepad One of your notepads
@serial The end of the latest Serial Monitor capture
@web An online search. Off by default; turn on noyce.agents.context.web.enabled

When the Semantic Search index is built, relevant code from it is added to agent prompts as well.

Change an agent's instructions#

Edit Agent System Prompt… lists the agents and shows which ones have a custom prompt. Pick one to copy its built-in prompt into .noyce/agents/prompts/<agent>.md and open it; your edited copy is used from then on. Delete the file to go back to the built-in prompt.

Prompts saved by earlier versions in .noyce-agents/prompts/<agent>.md are still used when there is no copy under .noyce/. When you pick one of those agents, you are asked whether to move its file to the new location; nothing is deleted unless you choose Move.

Firmware Validation Loop#

Build, flash, watch the output, propose a repair, and build again, until the output matches what you expect or the attempts run out. Open it with ⌘⌥N then V. Each proposed repair is staged as a change set; it is never written straight to your files. The loop needs noyce.agents.enableShell, and offers to turn it on for the workspace.

Fix build errors#

Fix Build Errors with AI sends the errors in the Problems list, with a few lines of source around each, to the Coder agent and asks for a patch. A diff opens for each file, then you choose Stage all fixes, Stage per file… or Discard. Nothing is written to your source: staged fixes wait as a change set in Evidence Records for you to approve. Warnings are included only if noyce.agents.buildfix.includeWarnings is on.

Source control and terminal#

  • Generate Commit Message in the Source Control title bar writes a message for your staged changes (or all changes when nothing is staged) into the commit message box, following Conventional Commits unless you turn off noyce.agents.scm.conventionalCommits. Nothing is committed for you.
  • Explain My Changes, next to it, opens a plain-language summary of the same diff.
  • In the terminal, ⌘K opens Generate Terminal Command (replacing the Code-OSS Clear shortcut there). Describe what you want; the command comes back with Insert into terminal, Insert and run and Copy. Commands that look dangerous never offer Insert and run.
  • Explain Terminal Failure explains the output you have selected in the terminal, or output you paste.

Agent settings#

Find these in Settings under Noyce Agents. Every feature setting ending in .enabled turns its feature off when cleared.

Setting Default What it does
noyce.agents.enableShell off Lets agents run shell commands in the workspace (120-second limit). Needed for verifyCommand and the Firmware Validation Loop.
noyce.agents.verifyCommand empty The command an agent runs when it checks its own work, such as your build or test command. Without it, or with the shell off, the check uses the editor's diagnostics only.
noyce.agents.auditCapture on Records agent file edits and checks in the audit trail, .noyce/audit-ledger.json.
noyce.agents.gemini.fallbackChain Gemini 3.1 Pro … 2.5 Flash-Lite When a Gemini model reports a quota or rate limit, it rests for the time Gemini asks (or 60 seconds) and the next model in the list is used.
noyce.agents.scm.maxDiffChars 24,000 How much of a diff is sent for commit messages and summaries.
noyce.agents.buildfix.contextLines, maxFiles 6, 8 Source lines around each error, and how many files (those with the most errors) are sent.
noyce.agents.firmwareLoop.* The loop's build, flash and observe commands, success pattern, attempts (3), time limit (120 s) and auto-apply (off).
noyce.chat.enableShell off Lets the @noyce participant in the Chat view run shell commands. Separate from noyce.agents.enableShell.
