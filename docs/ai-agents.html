AI & agents

The AI Orchestrator and its 15 agents, the agents chat panel, inline edits, project rules and memories, the firmware validation loop, commit messages and terminal help.

Every AI feature runs on the model you choose in AI Models. For the screenshots on this page that was Ornith (ornith-1.5-35b-a3b), served by vLLM on a machine on the local network.

AI Orchestrator#

A kanban board where agents work through tasks for this project. Open it with ⌘⌥N then O or Noyce AI: Open AI Orchestrator.

Reading the board

  • The header shows the model in use, its context size, live token rate, and how many calls are running. It is a readout; choose models in Models.
  • The strip shows concurrency, sprint progress, how many cards wait for your review, and the handoff chain of the 15 agents.
  • The columns: To Do (ready for an agent), In Progress (an agent owns it), Handover (the agent is done and you need to review it), Done. Status / By agent switches the grouping.

Adding work

  • Type tasks in Backlog, one per line. Prefix a line with an agent to route it (coder: implement voltage clamp) and add [high] for priority. Then Add to sprint or Add to backlog.
  • Generate via Orchestrator on the Compliance Dashboard adds one card per open objective.
  • Authoring a DO-178C document adds a card for that document.

Running it

  • Run next runs the next card. Run sprint works through the sprint. Run full pipeline runs the multi-agent pipeline on an objective you type in the box next to it.
  • Auto-run keeps the sprint moving as cards finish.
  • Agent output opens one tab per agent with its streamed output, its reasoning, and the actions it took.

What agents produce. Documents and evidence are written into .noyce/ as drafts for you to review. Code is never written to your files directly: with Auto-apply agent code off you choose Stage all as change set in the agent's output; with it on, the change set is staged for you. Either way it waits in Evidence Records → Change sets for a person to approve.

The board is saved per project in .noyce/orchestrator-tasks.json, so cards from one project never appear in another.

The 15 agents#

Agent Typical work
System Designer Breaks a goal into tasks and design.
Software Engineer Writes code (route with coder:).
Test Engineer Writes tests.
Code Reviewer Reviews changes.
Doc Generator Drafts documents and objective evidence.
Traceability Monitor Checks trace links.
MISRA Code Fixer, CBMC Fixer, CodeQL Fixer Propose fixes for findings, as change sets.
Compliance Author Writes compliance evidence.
Doc Author, Doc Reviewer Author and review DO-178C document sections.
UI/UX Designer, Frontend Developer, API Integrator General roles, not firmware-specific.

Give any agent its own model in AI Models → Agent Role Assignment.

Agents chat#

A chat panel in the secondary sidebar, with a choice of agent persona. Open it with ⌘⇧A or Noyce AI: Open Agents Chat (⌘⌃I).

  • Switch agent with ⌘K ⌘A, attach a file with ⌘⇧O, search the thread with ⌘F, and stop a reply with ⌘..
  • Agent History keeps every thread, with export, delete and re-run.
  • Edits an agent makes from the chat can be undone with Revert Last Agent Edit or Revert All Agent Edits.

In the Code-OSS Chat view, the @noyce participant answers in agent, ask or edit mode and has /fix, /test, /explain and /trace.

In the editor#

  • Inline edit: select code, press ⌘K ⌘I, describe the change, and review the inline diff. Enter accepts, Esc rejects.
  • Composer (⌘⌥K) opens a review panel for an agent's changes across several files, with a diff per file.
  • CodeLens actions above functions: Refactor with Coder, Audit MISRA with Reviewer, Generate Tests with Tester.
  • Generate Driver from Datasheet (⌘⌥D) drafts a driver from a datasheet you attach.
  • Fix with Noyce appears as a quick fix on MISRA diagnostics.

Inline completions are off by default; turn them on with the noyce.agents.inline.enabled setting.

Context you give the agents#

Kind Command Stored in
Project rules: standing instructions, such as your coding standard Create Project Rule, Show Project Rules .noyce/rules/*.md
Notepads: reusable notes you can attach Create Notepad…, Show Notepads… .noyce/notepads/*.md
Memories: facts the agents keep about the project Show Project Memories .noyce/memories.md

When the Semantic Search index is built, relevant code from it is added to agent prompts as well.

Firmware Validation Loop#

Build, read the errors, propose a repair, and build again, until the build passes or you stop it. Open it with ⌘⌥N then V. Each proposed repair is staged as a change set; it is never written straight to your files. Fix Build Errors with AI does a single pass.

Source control and terminal#

  • Generate Commit Message and Explain My Changes sit in the Source Control title bar. They read your staged diff and fill the commit message box.
  • In the terminal, ⌘K opens Generate Terminal Command: describe what you want and get one command, with Insert, Run or Copy. Commands that look dangerous are flagged for review before you insert them. Explain Terminal Failure explains the last error.
