ISO 26262 and IEC 61508 method tables

How a project certified to ISO 26262 (ASIL) or IEC 61508 (SIL) is graded against the software method tables - the built-in tables, two-person verification and overrides, a licensed import, and what the Compliance Run grades.

ISO 26262-6 and IEC 61508-3 do not list objectives the way DO-178C Annex A does. They list methods and techniques, each with a recommendation per integrity level: ++ highly recommended, + recommended, o no recommendation (ISO 26262, per ASIL A–D); HR, R, - and NR not recommended (IEC 61508, per SIL 1–4). Noyce IDE grades a project against these tables with the same rules as Annex A: a built-in table that counts only after two people verify it, signed overrides, or a licensed table you import.

Which framework a run grades#

The Compliance Run grades the framework and level your project has recorded on the Compliance Dashboard. A recorded DO-178C software level takes precedence, so an existing DO-178C project is graded exactly as before. Otherwise the run uses the ISO 26262 ASIL or the IEC 61508 SIL you recorded. No level is assumed: with none recorded, Take a run asks you to choose one.

ASIL QM levies no Part 6 method table, so a run at QM is refused with "ASIL QM levies no ISO 26262-6 method table".

The built-in tables#

Standard Tables built in Entries Cells Least certain Not entered
ISO 26262-6:2018 6-1 to 6-12 79 316 88 4 (row 6-10.1d)
IEC 61508-3:2010 A.1, A.3, A.4, A.5, A.9, B.1, B.2, B.3, B.8, B.9 78 312 88 0

The tables hold entry ids and recommendation symbols only. They contain no method names, no clause text and no table titles; the short topic shown beside each table id is Noyce's own label. Every cell carries the provenance declared (producer noyce.builtin-iso26262-6 or noyce.builtin-iec61508-3).

Each entry records its source:

  • ISO 26262-6 Table 6-1 rows 1a–1h and IEC 61508-3 Table B.9 match a public reproduction (exida, "Software Metrics: ISO 26262 / IEC 61508", 2018).
  • Every other entry is the product author's transcription, not checked against a licensed copy.

Cells the author is least sure of are marked check first in the verification checklist. A cell that could not be stated from public sources is Not entered rather than guessed: it is neither met nor missed, and it has to be filled by an override before the table can be verified. Tables not listed above (for example ISO 26262-6 Tables 13 onward, IEC 61508-3 Table A.2) are not built in; they come only from a licensed import.

While the table is unverified, the Compliance Dashboard shows ISO 26262-6 method tables from built-in table, not verified (or the IEC 61508-3 equivalent): "Runs graded against it cannot be exported and plans stay draft until two rostered people verify it, or a licensed table is imported."

Verify the built-in table#

The checklist is the same as for Annex A. Two different people on the roster each confirm every cell against their own licensed copy.

  1. Select Verify… on the Compliance Dashboard, or open Evidence Records → ISO 26262-6 method tables (or IEC 61508-3 technique tables). The tab is named for the project's framework.
  2. Choose yourself under Verifier and name your copy under Licensed copy.
  3. Pick a table. For each entry and level, set what your copy says: Agree — …, Disagree — …, or, for a not-entered cell, State — … with the value your copy gives.
  4. Agree with the rest of table marks every untouched stated cell as agreeing. Not-entered cells are left for you to state.
  5. When every cell is marked, select Sign verification.

The table becomes Built-in, verified when two distinct rostered people have signed, every value each stated equals the effective cell, no cell is still not entered, and neither record is stale. Each record carries the SHA-256 of the table it checked; an override or a product update re-opens it. Records are stored one file per record under .noyce/process/iso26262-6-verification/ or .noyce/process/iec61508-3-verification/, and are release inputs.

Under Cells to resolve, a disagreement or a stated not-entered cell is turned into an override: choose Override recorded by, give a Reason, and select Override to value. The override is a signed record; both verifiers then verify the changed table again.

Import a licensed table#

Open Import a licensed table instead at the bottom of the checklist. Write blank template writes .noyce/compliance/<standard>-licensed.template.json with every entry id and empty cells. Fill every cell (and, optionally, the method names) from your licensed copy, paste the JSON, choose Imported by and select Import and sign. The table is stored at .noyce/compliance/iso26262-6-licensed.json or .noyce/compliance/iec61508-3-licensed.json with its content hash, and takes precedence over the built-in table. A table edited after import no longer verifies and is ignored.

What the run grades#

An ISO 26262 or IEC 61508 run shows Highly recommended methods as its headline figure and a method-table section in place of Annex A. Each entry reads its recommendation at your level, then:

  • Evidenced: a producer that genuinely applies the method ran and passed.
  • Failing: that producer ran and failed (for example a levied coverage criterion below 100%).
  • Open: highly recommended or recommended, with no evidence. Many methods (walk-throughs, design notations, defensive implementation) have no producer in Noyce IDE; a review record or a justification closes them.
  • Advisory: evidence exists but cannot close anything (heuristic, or declared without a rostered signer).
  • Not levied: no recommendation at this level.
  • Not entered: the table does not state the cell.

Which producers evidence which entries:

Producer ISO 26262-6 IEC 61508-3
MISRA C analysis 6-1.1b, 6-1.1c, 6-7.1h, 6-10.1g A.3.3, A.4.5, A.9.3, B.1.1

Data and control coupling (measured) 6-10.1f, 6-12.1b A.5.7

Measured timing is a resource-usage evaluation and performance test, never a WCET analysis. CBMC is bounded model checking, not a formal proof.

Structural coverage thresholds#

Only a criterion the table rates highly recommended at your level is levied, at 100%. A recommended criterion is measured and reported but never failed, because both standards let a justified alternative replace it. From the built-in tables:

Level Statement Branch MC/DC
ASIL A 100% levied recommended recommended
ASIL B 100% levied 100% levied recommended
ASIL C recommended 100% levied recommended
ASIL D recommended 100% levied 100% levied
SIL 1 recommended recommended recommended
SIL 2 100% levied recommended recommended
SIL 3 100% levied 100% levied recommended
SIL 4 100% levied 100% levied 100% levied

Overrides and an imported table change these thresholds. The run lists the wording for your level, for example "MC/DC: recommended at SIL 3 — measured and reported, not levied (a justified alternative may replace it)".

A run graded against the unverified built-in table records that in its configuration and cannot be exported: "ISO 26262-6:2018 recommendations from the built-in table — not yet verified against a licensed copy."

Limitations#

  • The built-in tables have not been verified by Noyce against licensed copies; your project's two verifications are what make them usable.
  • Only part of each standard's tables is built in (see the table above). IEC 62304 and EN 50716 have no built-in table.
  • The plans and documents Noyce IDE generates are DO-178C documents; ISO 26262 and IEC 61508 work products are not generated.
  • Most methods have no producer and stay open until a review or justification closes them outside the run.
