Known limitations

What Noyce IDE does not do yet, which surfaces show simulated or example data, and how the current release differs from v2.0.7. Read this before you rely on a number.

Noyce IDE is built on one rule: a surface either shows what it measured on your project, or it says it has nothing. This page lists every place where that rule has a caveat, so you are never surprised by it.

Compliance#

  • The certification package is sealed, not signed. Sections are SHA-256 hashed and the digest is anchored to the audit trail; there is no private-key signature.
  • Annex A objective text is not included. It is licensed by RTCA. Import your own copy; until then plans and summaries stay marked DRAFT.
  • Object Code Traceability needs an analysis produced outside the app. The view suggests npm run socta, a script in the Noyce IDE source repository that the installed app does not include.
  • External requirement tools are not connected. Jama Connect and IBM DOORS Next do not sync. Export ReqIF or CSV from them and import the file in Requirements Authoring.

Analysis#

  • CodeQL scans of TI projects are buildless. CodeQL cannot trace the TI armcl compiler, so the scan reads the sources with guessed include paths and defines. The dashboard says so, and a count of 0 from such a scan is not conclusive. See Code Scanning.
  • Semantic Search needs a server that serves embeddings. A chat-only server, such as a vLLM instance serving one generative model, answers /v1/embeddings with 404.

Build and team#

  • Builds cover TI Code Composer Studio and STM32CubeIDE projects. The status bar items and the Noyce build tasks appear only when the folder has a CCS .cproject. An STM32 project gets its ⇧⌘B task from Noyce STM32: Regenerate Workspace Files, and that task runs CubeIDE's own makefiles; makefiles generated on another computer fail there, so use the Build view's Build with a generated makefile.
  • A TI build links only with armcl and a linker command file whose libraries all resolve; otherwise it compiles only, and there is no .map for Firmware Memory.
  • Team Activity is always empty and Review Workflow cannot sync: no collaboration backend is connected.
  • Build Status and the Build view's History tab differ. Build Status lists your last 10 builds, TI CCS and STM32. The Build view's History tab still shows only the latest CCS build of each configuration. No CI system is connected.

Hardware#

  • Simulated data. Signal Viewer, Live Data Dashboard, HIL Test Runner, Energy Profiler and Data Recorder show generated data under a "simulated" banner. Do not use their numbers as measurements.
  • Fault Analyzer opens on a built-in example dump, marked as an example, until you paste your own. It does not read faults from a live target.
  • Register Inspector opens on a sample device when the project has no .svd file and you have not loaded one. When it has detected your part it says the sample is not that part.
  • Modbus Monitor starts with an example register map, labelled as one. The serial connection is real.
  • Firmware Memory cannot establish worst-case stack depth for TI builds. TI's compiler does not write -fstack-usage records, so the view shows the configured stack size instead.
  • Peripheral Registers is derived from the pin configuration, not read from the target.
  • FPGA synthesis is not connected. FPGA Workspace and Synthesis Dashboard show an example report, marked as one, and Run synthesis builds nothing.

AI#

  • Three Orchestrator agents are general web roles (UI/UX Designer, Frontend Developer, API Integrator) and are not specific to firmware.
  • There is no in-app updater. See Update.

Differences in v2.0.7#

These docs describe the current release. If you are still on v2.0.7, these behave differently:

  • Assurance level. The level in Settings → Compliance Standards is not saved, and Compliance Run, Certification Readiness, Data & Control Coupling, MC/DC Coverage and Evidence Records assess Level A whatever the project's level. Set the level in the Compliance Dashboard header.
  • Annotation Navigator labels every @req tag Verified, whether or not a test exists. Read it as "tag found".
  • Classified mode has no effect: no feature reads the toggle.
  • Cloud API keys are kept in the IDE's local web storage, not the keychain.
  • Build. There are no build tasks, status bar items or ⇧⌘B; build from the Build Pipeline view, which shows a stage list, a generated YAML tab and log lines instead of real artifacts.
  • Firmware Memory reads GNU ld map files only, not TI armcl maps.
  • CodeQL on a TI project extracts no files and reports 0 alerts.
  • Test Explorer does not record Run All results; Analyze with AI Agent on a failed test does nothing.
  • The Firmware Validation Loop stops after the first staged repair.
  • STM32 memory reads, RTT and the Debug State view cannot attach a probe themselves; attach in the Debug Probe view.
  • High-Level Design draws only with a Gemma model on LM Studio, draws its boxes without labels, packs source files in name order so the first large file can take the whole request, and shows nothing at all if one line of the model's diagram is invalid.
  • Document Reader offers Edit on generated documents, and the edits are lost when the document is rebuilt from its source.
  • Evidence Records judges verification-case independence by name, and Remove on the roster does not ask for confirmation.
  • Noyce: Import Project in the Command Palette only picks a folder, Project Templates create an in-memory demo, and ⌘⌥N M and ⌘⌥N P each open two views.
  • Data Recorder shows no "simulated" banner, and Modbus Monitor shows an example device's name ("Dynamo Modbus Explorer").
  • The Trace agent's output tab shows fixed coverage figures (100% traced, 96% covered) that are not measured.
  • Fix with Noyce asks the model for the whole file, so a fix can rewrite code far from the finding, such as the file header; the dialog lists the entire file instead of the change.
  • BoM Studio and Data Recorder exports do not download inside the IDE window.
  • FPGA Workspace: Run synthesis reports "Synthesis complete" without running anything, over a fixed example report with no banner.
  • Load demo project on the start tab opens an error.
  • Register Inspector never opens the project's own SVD file; load it with Load .svd… every time.
  • Pipeline Status in the sidebar is empty, or reads "Pipeline idle". It does not list your builds.
  • The sidebar view listing serial ports is called Workspace Signals, and the status bar reads No Probe when there are no serial ports; it has nothing to do with debug probes.
  • Some agent commands appear in the Command Palette as "Noyce Agents: Noyce: …".
  • Mouser and DigiKey credentials are plain settings, not stored in the keychain.
  • Custom agent prompts live in .noyce-agents/prompts/. The current release reads them from there too, and offers to move them to .noyce/agents/prompts/.
  • STM32 Debug State memory watches update only when you select Refresh, and take hex addresses only.
