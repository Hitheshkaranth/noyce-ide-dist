Known limitations

What Noyce IDE v2.0.7 does not do yet, where a control looks active but is not, and which surfaces show simulated data. Read this before you rely on a number.

Noyce IDE is built on one rule: a surface either shows what it measured on your project, or it says it has nothing. This page lists every place in v2.0.7 where that is not yet fully true, so you are never surprised by it. Items marked fixed on main are corrected in the source and ship with the next release; the installers for v2.0.7 still behave as described.

Compliance#

  • Assurance level in Settings has no effect. Set the DAL in the Compliance Dashboard header. The Assurance Level in Settings → Compliance Standards is not saved. Fixed on main for the next release.
  • Some views always assess Level A. Compliance Run, Certification Readiness, Data & Control Coupling and MC/DC Coverage use DAL A whatever level the project is set to. Fixed on main for the next release.
  • The Annotation Navigator's "Verified" label means "tag found". Every @req tag is labelled Verified and every @verification tag Needs review, whether or not a test exists. Use the Compliance Dashboard's Verification count instead. Fixed on main for the next release.
  • The certification package is sealed, not signed. Sections are SHA-256 hashed and the digest is anchored to the audit trail; there is no private-key signature.
  • Annex A objective text is not included. It is licensed by RTCA. Import your own copy; until then plans and summaries stay marked DRAFT.
  • Object Code Traceability needs an analysis produced outside the app. The view suggests npm run socta, a script in the Noyce IDE source repository that the installed app does not include.
  • Semantic Search needs a server that serves embeddings. A chat-only server, such as a vLLM instance serving one generative model, answers /v1/embeddings with 404.
  • External requirement tools are not connected. The Jama Connect, IBM DOORS Next and ReqIF options in the Requirements view do not sync anything. Import ReqIF or CSV files through Requirements Authoring instead. Fixed on main for the next release.

Projects and navigation#

  • Noyce: Import Project in the Command Palette only picks a folder. Use Import Project on the start tab for the import wizard. Fixed on main for the next release.
  • The search box on the start tab does nothing. Use the Command Palette.
  • Project Templates create an in-memory demo, not files on disk. Try the demo opens a sample file in a demo editor. Fixed on main for the next release.
  • Two shortcuts are shared. ⌘⌥N M is bound to both MISRA Diagnostics and Firmware Memory, and ⌘⌥N P to both Pin Configurator and Project Graph. Use the Command Palette for the one you need. Fixed on main for the next release.

Records and documents#

  • Evidence Records evaluates at Level A. Admissible verification cases and tool qualification levels in that view assume Level A.
  • Verification cases judge independence by name. A case's reviewer only has to differ from its author by name; the Reviews tab, which uses the roster, is the stricter check.
  • Removing a person from the roster does not ask for confirmation.
  • Document Reader edits are temporary for generated documents. Edit changes the .docx; reopening a DO-178C or Markdown-based document rebuilds it from its source.
  • High-Level Design needs a Gemma model on LM Studio. With any other model it explains why and does not draw.

Team and build#

  • Team Activity is always empty and Review Workflow cannot sync: no collaboration backend is connected.
  • Build Pipeline runs real builds only for TI Code Composer Studio projects. Its YAML Source tab is generated for reference, and Artifacts lists log lines that mention outputs.
  • Test Explorer's Run All results are not recorded, and the Analyze with AI Agent button on a failed test does nothing. Requirement-based and target runs are recorded.
  • The Firmware Validation Loop stops after the first staged repair, whatever maxAttempts is set to. Apply the change set and run it again.
  • STM32 Read Target Memory, RTT streaming and the STM32 Debug State registers need an attached probe that these commands cannot attach themselves. Use the Debug Probe view.
  • Build Pipeline (original sentence kept below) The Pipeline Status tree in the sidebar always reads idle; no CI system is connected.

Hardware#

  • Simulated data. Signal Viewer, Live Data Dashboard, HIL Test Runner and Energy Profiler show generated data under a "simulated" banner. Data Recorder also plots generated data, and in v2.0.7 it does not show the banner. Fixed on main for the next release.
  • Fault Analyzer opens on a built-in example dump, marked as an example, until you paste your own. It does not read faults from a live target.
  • Register Inspector opens on a sample device until you load your own .svd file, even when it has detected your part. Fixed on main for the next release.
  • Modbus Monitor shows an example device's name and register map ("Dynamo Modbus Explorer", DCO-5000 holding registers), not your project's. The serial connection is real. Fixed on main for the next release.
  • Firmware Memory reads GNU ld map files only. TI armcl map files are not parsed yet.
  • Peripheral Registers is derived from the pin configuration, not read from the target.
  • BoM Studio's export may not download inside the IDE window.

AI#

  • Classified mode has no effect yet. The status bar toggle is stored, but no feature reads it. Use a local model to keep code on your machine. Fixed on main for the next release: with Classified on, calls to cloud providers from the Noyce IDE window are refused. The agents chat panel is not covered yet.
  • Cloud API keys are stored in the IDE's local web storage, not the operating system keychain. Local-server and per-agent keys use the keychain. Fixed on main for the next release.
  • The Trace agent's output tab shows fixed coverage figures (100% traced, 96% covered) that are not measured.
  • Three Orchestrator agents are general web roles (UI/UX Designer, Frontend Developer, API Integrator) and are not specific to firmware.
  • There is no in-app updater. See Update.
