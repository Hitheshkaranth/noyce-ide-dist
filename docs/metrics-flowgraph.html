Metrics, flowgraph and cross-reference

Per-function control-flow graphs, code metrics computed from the program model and checked against a quality model, and a cross-reference of every global and call.

Flowgraph & Cross-Reference shows each function's control-flow graph, its metrics against your quality model, and where each symbol is defined, read, written and called. Everything here is computed from the program model and tagged Derived. Open it with Noyce Compliance: Open Flowgraph & Cross-Reference, from the Compliance hub, or with Open flowgraph on a Quality Trend hotspot.

Compute metrics#

Select Compute metrics. It rebuilds the program model, then computes metrics for every function, and writes .noyce/analysis/metrics.json. Until then the view reads "Not measured — build the program model". The header shows how many functions and translation units were measured, any parse errors, and the model and engine version.

The function list can be searched, filtered to Violations, and sorted by Complexity or File order. It shows V(G), ev(G), nesting depth and the number of violations.

The metrics#

Metric How it is computed
Cyclomatic complexity V(G) E − N + 2 over the function's control-flow graph, at least 1.
Essential complexity ev(G) V(G) after repeatedly collapsing structured single-entry, single-exit subgraphs.
Maximum nesting, statements From the syntax tree.
Knots Pairs of jump arcs that cross, in source-line order.
Halstead Operators and operands (n1, n2, N1, N2), length, vocabulary, volume, difficulty (n1/2 · N2/n2) and effort (difficulty × volume).
Lines Physical, blank, code and comment lines; comment density = comment lines ÷ code lines.
Fan-in, fan-out Distinct callers and callees; pointer calls and parameter count.
Returns Return points.

The quality model#

Limits live in .noyce/quality-model.json, written with defaults from the HIS Source Code Metrics 1.3.1 recommended limits the first time metrics are computed: cyclomatic ≤ 10, essential ≤ 4, nesting ≤ 4, knots 0, statements ≤ 50, parameters ≤ 5, fan-out ≤ 7, fan-in ≤ 5, returns ≤ 1, comment density ≥ 0.2. Edit the file for your project. A value violates a limit only when it is strictly outside it. The Metrics section of a function lists its violations as Metric, Value, Limit.

Control-flow graph#

The Control flow graph section draws the selected function: a diamond is a decision, a dashed curve is a back-edge, and dotted or muted blocks are unreachable. Select a block to open its source line.

Cross-reference#

For the selected function, Globals accessed by function lists each global with its reads and writes. Choose any symbol to see its Definitions, Declarations, Reads, Writes, Callers and Callees.

Quality Trend#

Capture Snapshot in Quality Trend now uses these derived metrics. If the model cannot be built, it falls back to the older text-based estimate, says so, and only on that fallback shows the maintainability proxy ("Proxy, not the SEI index"). On the derived path maintainability is not computed: "no validated maintainability formula".

Limitations#

  • Coverage is not drawn on the flowgraph yet; the legend says "Coverage overlay: not measured".
  • Symbols are matched by name, so two static functions or globals with the same name in different files are conflated.
  • Calls and accesses through unresolved pointers are excluded from the cross-reference (their count is shown).
  • Comment lines are counted for each translation unit's main file only, not its headers.
  • Per-level limits in the quality model (byDal) are not applied by the view, and Quality Trend's "over 10" complexity count uses a fixed limit of 10 rather than the quality model.
  • Compute metrics cannot be cancelled from this view.
