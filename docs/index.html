Noyce IDE documentation

Noyce IDE is a Code-OSS workbench for embedded firmware that has to certify. These docs show how to install it, open a real project, and use every surface, with screenshots taken from the IDE running on production TI Tiva firmware.

What Noyce IDE does#

Noyce IDE is a desktop IDE built on Code-OSS, the open-source core of Visual Studio Code. You edit firmware in a normal editor, and next to it the IDE adds surfaces that each measure one kind of engineering evidence from the project you have open:

  • Know the code: Project Graph, System Architecture, Semantic Search, and Register Knowledge, which indexes your microcontroller's reference manual and links its registers to the code that uses them, citing the page.
  • Prove it: MISRA C diagnostics, CBMC formal verification, CodeQL code scanning, and measured MC/DC coverage.
  • Trace it: requirements, the Traceability Graph, and the DO-178C Annex A objective model.
  • Author and certify: the 17 DO-178C life-cycle documents, compliance runs, evidence records, a hash-chained audit trail and a certification package.
  • Agents: an Orchestrator with 15 agents, plus an agents chat panel. Code changes from the Orchestrator and from Fix with Noyce are staged as change sets you approve before anything is written. Inline edits in the editor are previewed as a diff you accept or reject, and edits made from the chat can be reverted.

How it fits together#

Three ideas run through every page of these docs:

  • Measured, or marked. A surface shows what a real tool measured on your project, or it says nothing was measured. Sample data is labelled and never counts.
  • Agents draft, people decide. Agents write drafts, fixes and evidence. Nothing an agent produces satisfies an objective until a named person on your roster accepts it, and fixes from Fix with Noyce, the fixers and the Orchestrator reach your code only as change sets that a person approves.
  • Everything lands in .noyce/. Results, records and documents live in one folder in the project, outside version control, and the important ones are hashed so changes are detectable.

How these docs were made#

Every screenshot in these docs was taken from Noyce IDE v2.0.7 running on a copy of the Canister Main Controller firmware, a production TI Tiva TM4C1294 project. The numbers you see, such as 624 stored MISRA findings, 29 requirements and 71 Annex A objectives, are what the IDE measured on that copy. Empty states are shown as they are: where a tool has not been run, the screenshot says so.

Note

The copy includes uncommitted changes from earlier Noyce IDE sessions: @req and @verification comment blocks at the top of eight source files, and edits to a few functions. They are why the Annotation Navigator finds requirement tags. Nothing was written to the project to make these docs; Noyce IDE keeps what it generates in the project's .noyce/ folder. See The .noyce folder.
