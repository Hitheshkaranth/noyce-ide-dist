Quick start

Open a firmware project, scan it, and read your first static-analysis findings and compliance picture, in about ten minutes.

This walkthrough uses the screenshots from a real project, the Canister Main Controller firmware (TI Tiva TM4C1294, Code Composer Studio). Any C firmware project works the same way.

Before you begin#

  • Install Noyce IDE.
  • Optional: connect a model. Steps 1 to 4 below work without one.
  • Optional: install cppcheck for full MISRA analysis (brew install cppcheck on macOS).

1. Open your project#

On the Noyce IDE start tab, choose one of:

  • Open folder… opens any folder as it is.
  • Import project… starts the import wizard; Import and build follows it through for a TI and an ST project. Pick Code Composer Studio (.ccsproject), STM32CubeIDE (.ioc), MPLAB X (nbproject) or Generic Folder. The wizard detects the microcontroller and, when it recognises an ST or TI part, downloads that part's reference manual in the background and indexes it for Register Knowledge. That download needs a network connection; everything else works offline.

Note

Use the Import Project button on the start tab. The Command Palette entry Noyce: Import Project only picks a folder and does not run the wizard.

Opening a project creates a .noyce/ folder inside it for everything Noyce IDE generates. Its life-cycle data is meant to be committed with the project; its own .gitignore keeps out the caches and scratch files. See The .noyce folder.

2. Scan for requirement annotations#

Press ⌘⌥N then S (CtrlAltN then S on Windows), or run Noyce Compliance: Scan Workspace. Noyce IDE finds every @req and @verification tag in your source, shows the counts, and opens the Annotation Navigator.

Important

A tag is not evidence. The navigator labels a requirement Verified only when an executed test result backs it; tagged requirements without one read Needs review. The Compliance Dashboard shows the verified count, which on this project reads 0 of 29.

If your code has no tags yet, that is fine. Requirements can also come from documents and imports; see Requirements & traceability.

3. Run static analysis#

Open MISRA Diagnostics from its tile, or run Noyce Compliance: Open MISRA Diagnostics, then select Scan. Findings are grouped by severity (Mandatory, Required, Advisory) and by the tool that reported them. Select a finding to see its rule, file and line, with Open in Editor and Fix with Noyce.

Important

Findings from the built-in heuristic scan are labelled not evidence. Only findings from a real analyzer (cppcheck with the MISRA addon, or clang-tidy) count toward compliance.

4. See where the project stands#

Open Compliance (⌘⌥N then C). The Compliance Dashboard grades the project against DO-178C and shows each Annex A objective with the evidence behind it.

An objective is only satisfied when its own evidence exists and a person has reviewed it. On a project that has just been opened, most objectives read open or partial; that is the honest starting point, not an error.
