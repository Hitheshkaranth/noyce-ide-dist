CHAPTER 01 · ONE IDE, EVERY ARTIFACT

Code, evidence, and silicon —
finally on the same desk.

Noyce extends the Code-OSS shell you already trust with first-class surfaces for requirements, traceability, MISRA, MC/DC, pin configuration, and on-target debug. No tab-hopping between five tools.

Compliance

Evidence in the editor

DO-178C Table A objectives, ISO 26262 work products, MISRA-C:2012 advisories, MC/DC coverage — surfaced inline alongside the code they govern.

Hardware

Aware of the silicon

Pin mux, peripheral registers via SVD, RTOS task viewer, debug-probe sessions, Cortex-M fault decoder, and linker memory maps — wired straight into the workbench.

AI

A team, not a chatbot

Six specialist personas — Designer, Coder, Tester, Reviewer, Doc Specialist, Traceability Monitor — orchestrated against the safety case, not your blank line.

CHAPTER 02 · MULTI-AGENT ORCHESTRATOR

Six specialist agents,
one auditable thread.

Bring your own provider — Anthropic, OpenAI, Google Gemini, Mistral, or run fully on-prem through Ollama or LM Studio. The orchestrator routes by latency, cost, and confidence, and every action is signed against the requirements graph.

PERSONAS · LIVE
System Designer Coder Tester Reviewer Doc Specialist Traceability Monitor

The Designer decomposes.

Takes a high-level requirement — "the brake actuator shall respond within 50 ms under ASIL-D conditions" — and emits low-level design items, interfaces, and traceability stubs.

$ noyce decompose REQ-014 --target stm32h7

The Coder writes —
the Reviewer pushes back.

Coder drafts the implementation with the SVD and HAL in context; Reviewer scrutinises against MISRA-C, fixed-point arithmetic, ISR safety, and the project's deviation register.

/* MISRA-C:2012 R.11.5 — explicit cast required */

The Tester proves it.

Generates MC/DC harnesses, fault-injection scenarios, hardware-in-the-loop scripts, and ties verification artifacts back to the originating requirement.

tst: "TST-204 timer accuracy" · mc/dc · 128 iter

The Doc Specialist captures it.

Writes the SDP, SDD, SVP, and review minutes from the live workspace — never from your memory three months later. Section numbers, deviations, and signatures all stay linked.

SDP §4.2 watchdog reset rationale · drafted

The Traceability Monitor stitches.

Maintains the REQ → Design → Code → Test thread continuously. Breaks the build when a requirement loses a downstream artifact. Records every link in the audit log.

trace: 1,284 links · audit-log ready for export
CHAPTER 03 · HARDWARE-AWARE EDITING

The editor reads the datasheet
so you don't have to.

First-class support for STM32, TI Tiva, Microchip PIC32, Raspberry Pi RP2040, NXP i.MX RT, and generic Cortex-M. Pin mux, SVD-aware peripheral registers, RTOS task viewer, Cortex-M fault decoder, and linker memory maps — all visible without leaving the file.

Pin mux that knows the board.

Drag a peripheral onto the chip and Noyce resolves the alternate function, conflicts, and pin-level electrical constraints in real time. Exports HAL init code, device-tree fragments, or AUTOSAR ECU config.

PA9=USART1_TX · alt-fn 7 · drive=high · resolved

Peripheral registers, SVD-aware.

Hover any MMIO write to see the register, its fields, reset value, and access semantics — pulled straight from the vendor's SVD. Bitfield ranges, enumerated values, and read-modify-write traps surface inline.

RCC->AHB1ENR = RCC_AHB1ENR_GPIOAEN;

RTOS task viewer, on target.

Live task list, stack high-watermark, mutex graph, and deadline misses for FreeRTOS, Zephyr, ThreadX, and bare-metal cooperative schedulers. Attach in 200 ms over SWD or JLink.

task_safety · prio 31 · stack 412/1024 · RUNNING

Cortex-M fault decoder.

HardFault, BusFault, MemManage, UsageFault — decoded from CFSR/HFSR/MMFAR with the stacked frame walked back to source. No more reading hex registers off a serial console.

UsageFault: UNDEFINSTR @ 0x0801F2A4 · task_safety+0x18

Linker memory map.

Visualises FLASH, SRAM, CCM, and external regions; flags overflows before the link fails. Shows per-symbol cost so you can find the 4 KB of debug strings that wandered into your release image.

FLASH 612K / 2M · SRAM 128K / 512K · ok

ARCHITECTURE

Three layers, one contract.

A Code-OSS shell hosts the React UI; the React UI talks to a Rust sidecar over a typed RPC. The sidecar owns parsing, indexing, and the requirements graph — and stays out of the main thread.

Code-OSS Shell

The familiar workbench, extension host, and editor surface — extended with 10+ first-party packages. We don't fork Code-OSS; we extend it, so your settings.json, themes, and keybindings come along.

React UI

Every embedded-specific surface — pin mux, trace graph, compliance dash — is a React panel mounted into the workbench via the Webview API. State is pulled from the sidecar over rpc.invoke.

Rust Sidecar

Owns parsing (tree-sitter), SVD, MISRA, the trace store, and the project graph. Communicates over a typed JSON-RPC with cancellation, batching, and incremental subscriptions. Keeps the main thread free.
