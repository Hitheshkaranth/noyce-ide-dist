Noyce Agents

Six specialist agents,
one auditable thread.

Bring your own provider: Anthropic, OpenAI, Google Gemini, or Mistral. Or run fully on-prem through Ollama or LM Studio. The orchestrator routes by latency, cost, and confidence, and signs every action against the requirements graph.

Personas · live
System Designer Software Engineer Test Engineer Code Reviewer Doc Generator Traceability Monitor

The System Designer decomposes.

It takes a high-level requirement, such as "the brake actuator shall respond within 50 ms under ASIL-D conditions", and emits low-level design items, interfaces, and traceability stubs.

$ noyce decompose REQ-014 --target stm32h7

The Software Engineer writes.
The Code Reviewer pushes back.

The engineer drafts the implementation with the SVD and HAL in context. The reviewer scrutinises it against MISRA C, fixed-point arithmetic, ISR safety, and the project's deviation register.

/* MISRA C:2012 R.11.5: explicit cast required */

The Test Engineer proves it.

It generates MC/DC harnesses, fault-injection scenarios, and hardware-in-the-loop scripts, then ties each verification artifact back to the originating requirement.

tst: "TST-204 timer accuracy" · mc/dc · 128 iter

The Doc Generator captures it.

It writes the SDP, SDD, SVP, and review minutes from the live workspace, not from your memory three months later. Section numbers, deviations, and signatures stay linked.

SDP §4.2 watchdog reset rationale · drafted

The Traceability Monitor stitches.

It maintains the REQ → Design → Code → Test thread continuously, breaks the build when a requirement loses a downstream artifact, and records every link in the audit log.

trace: 1,284 links · audit-log ready for export

Pin mux that knows the board

Drag a peripheral onto the chip and Noyce resolves the alternate function, conflicts, and pin-level electrical constraints in real time, then exports HAL init, device-tree fragments, or AUTOSAR ECU config.

Peripheral registers, SVD-aware

Hover any MMIO write to see the register, its fields, reset value, and access semantics, pulled straight from the vendor's SVD. Bitfield ranges and read-modify-write traps surface inline.

RCC->AHB1ENR = RCC_AHB1ENR_GPIOAEN;

Live task list, stack high-watermark, and deadline misses for FreeRTOS, Zephyr, and ThreadX over SWD or J-Link.

Architecture

Three layers, one contract.

A Code-OSS shell hosts the React UI. The React UI talks to a Rust sidecar over a typed RPC. The sidecar owns parsing, indexing, and the requirements graph, and stays off the main thread.

Code-OSS Shell

The familiar workbench, extension host, and editor surface, extended with 10+ first-party packages. We don't fork Code-OSS, we extend it, so your settings.json, themes, and keybindings come along.

React UI

Every embedded-specific surface, from pin mux to the trace graph, is a React panel mounted into the workbench via the Webview API. State is pulled from the sidecar over rpc.invoke.

Rust Sidecar

It owns parsing (tree-sitter), SVD, MISRA, the trace store, and the project graph, over a typed JSON-RPC with cancellation, batching, and incremental subscriptions. The main thread stays free.
